01

Version and defaults

The lesson documents default depth 3, Agent concurrency 20 and no spend cap. This app pins the SDK and sets every cap explicitly. It uses three files rather than spending tokens on hundreds of workers; the same list/loop pattern illustrates larger runs.

02

Depth versus a refusal

At depth 1 a child may not receive Agent at all and can perform its own permitted work. Depth2 demonstrates a real grandchild. Do not claim an error string must appear when the capability was removed before a call.

03

Concurrency and incomplete work

The cap-one experiment asks for three background launches together. Native errors identify refused spawns. Reports must distinguish the admitted service from files that were never audited; do not infer complete coverage from a parent success result.

04

Spend estimate and expected SDK exception

Budget mode is intentionally tiny. It retains error_max_budget_usd and the following SDK exception as expected evidence. An in-flight request can exceed the estimate before enforcement; maxBudgetUsd is not an exact billing guarantee. Do not blindly sum cumulative result frames.

05

Opus 5 prompts and caps

The two Opus scenarios use an available Opus 5 model with either a custom instruction or claude_code preset plus an explicit user task. The model-specific delegation instruction steers behavior; depth/concurrency/spend controls remain necessary and explicit.

06

Native Workflow evidence

The actual Workflow tool launches the reviewed script. Native lifecycle hooks observe child starts and stops, PreToolUse hooks observe real service reads, and task_notification reports workflow completion. Workflow child messages are not all forwarded as assistant events; do not mistake an empty direct-Agent catalog for no workflow work.

07

Two concurrency mechanisms

CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS applies to direct Agent spawning. Workflow has its own CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS resource setting. Fan-out uses two workflow slots; the serial script awaits each task and uses one. Inspect native lifecycle timing without promising a speedup.

08

Script execution context

workflows/audit-parallel.js and audit-serial.js run inside the native Workflow runtime, which supplies agent, pipeline, phase and top-level return semantics. They are not standalone Node modules. The host reads only those packaged scripts and supplies one fixed script to the tool; students never need to paste arbitrary code.

09

Primary documentation

See https://code.claude.com/docs/en/agent-sdk/subagents and https://code.claude.com/docs/en/workflows for native caps, Workflow execution and version-dependent behavior.

2. Build string-valued cap environment

Pass depth and Agent concurrency through env strings. Workflow has a separate concurrency setting; a serial workflow uses one slot.

Source: src/scaling.ts · lines 11–20 · selected source; surrounding code omitted

export function capEnvironment(mode: Mode) {
  const limits = limitsFor(mode);
  return {
    CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH: String(limits.depth),
    CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS: String(limits.concurrency),
    CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS: String(
      limits.workflowConcurrency,
    ),
  };
}
